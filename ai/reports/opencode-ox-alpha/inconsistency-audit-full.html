01

Storage & query layer

31 FINDINGS · 5 HIGH · LIVE-DB VERIFIED

The biggest discovery of this audit is measured, not hypothetical: the "latest value" SQL returns an arbitrary row for thousands of item-variants because the history table contains same-timestamp ties with conflicting values — and the code manufactures those ties itself.

★ HIGH · 13,221 tie groups with conflicting values — "latest price" is a random draw

The latest-snapshot idiom used in 5 places (snapshotsRepo.ts:37,53, listings.ts:8,13,341):

8SELECT … FROM rap_snapshots
9GROUP BY item_id, pt, shiny HAVING captured_at = MAX(captured_at)

When several rows share the max captured_at, SQLite picks among them arbitrarily. Measured against your live DB: 13,221 groups have multiple rows at the identical max timestamp, and 100% of them carry conflicting values (example: one item has 7 rows at the same second ranging 92.4M → 384.7M). The mechanism that manufactures the ties is in the sync loop (§2): one run stamps all its snapshots with a single shared now, and the chroma/tier collapse (§2) guarantees multiple different values land on the same (item, variant, timestamp). Everything downstream — listings, detail pages, the sync dedupe map — reads a coin flip. The deterministic fix (ROW_NUMBER() OVER (PARTITION BY … ORDER BY captured_at DESC, value)) already exists in the same file for hour_exists; it's just not applied to the latest-value CTEs.

★ HIGH · The exists JOIN suppresses data for 2,569 live variants

The listing query joins exists snapshots with:

196LEFT JOIN latest_exists e
197  ON e.item_id = i.id AND e.pt = COALESCE(l.pt,0) AND e.shiny = COALESCE(l.shiny,0)

Under variant-per-row items, e.item_id = i.id already identifies the variant. The extra pt/shiny terms demand pt=0/shiny=0 whenever no RAP snapshot exists (the COALESCE defaults) — so a Golden variant with exists history but no RAP point joins nothing. Measured: 2,696 items have exists snapshots but no RAP snapshots; 2,569 of them are non-regular variants whose exists data is provably hidden by this predicate. The fix is to drop the pt/shiny join terms (item_id is sufficient) or key them off i.variant/i.shiny.

★ HIGH · Foreign keys are never enforced — and the migration path DROPs the items table

PRAGMA foreign_keys returns 0 on the live connection (better-sqlite3 default; nothing enables it). Every references() in the schema is decorative. Worse: migrateItemsTable() (client.ts:92-94) executes DROP TABLE items on legacy shapes — with FKs off, all snapshot rows survive pointing at deleted ids, permanently polluting LATEST aggregates with item_ids that match nothing. The migration can also fabricate collection = '' for legacy rows (client.ts:131), violating the reference silently.

02

Sync, ingest & identity

40 FINDINGS · WHERE THE TIES ARE BORN

The sync loop is where upstream reality is flattened into the storage model. Three flattenings are structural: variant dimensions dropped, partial failures reported as success, and collection-blind matching.

★ HIGH · Upstream variant dimensions (cv, tn, vr) are received and discarded

Real feeds carry chroma (cv=1..6), tier (tn), and vr labels — the project's own analysis script (src/test/03-variant-keys.ts:30-37) labels them. Production ingest (itemKey.ts:15-21) keeps only pt/sh. Combined with the shared-now batch design, every chroma/tier entry for the same base item lands on the same (item_id, pt, shiny, captured_at) with a different value — manufacturing the tie population measured in §1, making "current RAP" for those items an arbitrary pick, and interleaving distinct physical variants into one history series. There is no storage slot, key component, or slug token for cv/tn anywhere — the collapse is by design, not by accident. The dead items.tier column (in DDL + drizzle + migration, written never, read never, 0 non-null rows live) is the ghost of the attempt.

★ MED · Partial ingest failures report success — datasets can silently vanish

If fetchRap() or fetchExists() throws, the error is logged, the array becomes [], and execution continues to setSetting('sync.lastSyncAt', …) and a normal return. An hourly upstream outage yields zero snapshots but an advancing lastSyncAt; SyncResult carries no failure flag, so the cron log and POST /api/refresh cannot distinguish "no changes" from "ingest failed". Compounding: biggames.ts:56-62 validates the whole feed all-or-nothing — one malformed entry discards the entire dataset — and there is no retry/backoff, so a single transient blip costs a full cycle. Also: entries whose configData.id matches no item name are skipped with no counter, no log — a naming drift breaks ingestion for an item forever, silently.

Cross-cutting themes — what four independent lenses converged on

SYNTHESIS

1 · The write path and the read path disagree about what an item is

Ingest flattens upstream reality (drops cv/tn/vr, collapses variants, matches by bare name across collections) and stamps shared timestamps; the read layer then derives "latest" with a tie-ambiguous idiom over the flattened, tie-laden history, and derives variant identity from COALESCEd snapshot columns instead of the authoritative item row. Four independent auditors each independently arrived at this same pipeline-end-to-end story — the corruption is not a bug in one query; it is a contract mismatch between write-side flattening and read-side reconstruction.

2 · Labels exceed computation

ath/atl labeled all-time over ≤200 points; 30D/90D buttons over ~8-day data; a "total" that isn't total; a history count over a 200-row table; tracked/volatility constants rendered as analytics; "Updated" captions on the wrong snapshot clock. The UI consistently promises more than the query delivers.

3 · Built-then-abandoned surfaces

Cache invalidation helpers, the CronService admin API (tested, unrouted), drizzle-kit, detailPath/resolveIcon, home.ejs vs index.ejs, dead CSS generations, the tier column. Each is a reasonable step never connected.

4 · The toolchain gates the wrong things

63 green tests, zero of them touching a route — while the two homepage regressions happened in the unguarded surface. src/test excluded from typecheck but linted by accident. tests/ and root configs never typechecked. The gates are green because they look where the bugs aren't.
